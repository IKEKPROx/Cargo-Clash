用户要求：优化比赛界面；觉得视角太高，提议改第一人称；做手拿货物和毁坏货物的动画。我同意做第一人称，并告诉用户代价：看不到全场、要加鼠标操作、场景原本是按从上往下看做的。所以默认第一人称，加了 V 键切肩后视角，方便对比和兜底。开工前用户同意先提交，所以第 1–7 步单独在 `6c6c0f7`，这一步可以单独退回。

- **相机：** `FollowCamera` 改成第一人称（视野 64 度，眼高 1.28 米），走路有轻微起伏，冲撞时视野变宽，被撞倒时摔到地上看天。V 切肩后第三人称，碰到墙会拉近。直升机结尾的镜头不变。天空、雾、一圈山和云都补上了，因为现在能看到地平线。
- **操作：** 鼠标转视角（暂停菜单里能调速度），WASD 相对视线移动。左键或 F 砸货，右键或空格冲撞，方向键转视角（没鼠标也能玩）。比赛时鼠标被锁住，暂停和结算时放开。
- **手：** 新模型 `FirstPersonHands.fbx`（`make_hands.py`），袖子是队伍颜色。`FirstPersonRig` 用代码摆手：平时垂在两边跟着跑步摆动，反方手里拿锤子，冲撞时握拳，被撞时手飞起来。这些手和手里的货用单独一台相机画在最上面，不会插进墙里。
- **手拿货物：** 货物不再顶在头上。自己搬时抱在眼前，往前倾一点，货物的眼睛正好看着你，手指扣在两边。大箱子放得远一点，免得挡住太多。别人看到你抱在胸前，所以 `make_character.py` 改了 `Carry`、`Toss`，新增 `CarryBig`。两人合搬时手抓在箱子两端的把手上。
- **砸货：** 第一人称的锤子跟 `Smash` 动画同步。每挥一下：货物压扁弹起、飞出碎屑、闪一个漫画式的冲击星、镜头轻轻点一下。货物分三段变形（`make_cargo.py` 的 `_Damaged`）：纸箱塌陷撕开、板条箱裂开露出稻草、宝箱盖子被掀开露出金币。砸碎时裂成几块（`_Pieces`），连眼珠也飞出去，碎块和灰尘只在本地播放。挨过砸的货表情会一直害怕。
- **规则上的小改动，已尽量不影响平衡：** 砸货耐久改成每挥一下扣一次，不再每帧扣，这样碎的那一刻正好是锤子落下，总时间不变。瞄准由拥有者决定并把货的 ID 发给主机，主机只查距离。冲撞只撞面前的人。有延迟时连按两下 E 不会刚拿起就松手。人和人靠太近会慢慢分开，否则视角会跑到别人脑袋里。
- **比赛界面：** `BuildHud` 重写，和开始页面同一套风格：比分牌、准星（对准货物时变成绿圈或红圈）、带按键的提示、目标的耐久条、冲撞冷却条、半场开始的角色卡、暂停和结算页。`MiniMap` 是新的小地图。货车和大件有方向标记，身后或旁边 10 米内有敌人时屏幕边缘出现红箭头，被撞时显示撞击方向，这些是为了补上第一人称看不到全场的问题。
- **声音：** 新增 `swing`、`crack`、`coins`、`step`。`GameAudio.PlayAt` 让世界里的声音有远近和左右，这样能听到有人从背后过来。
- **性能：** 从 URP 渲染器里移除了 SSAO，关掉了没人用的深度和颜色纹理（见第 8 节第 24 条）。描边随距离淡出，否则远处的树只剩一团黑线。

## 4. 和设计文档不一样的地方

第一版里有几处是我自己决定的。用户试玩后只说了“还可以”，**没有逐条确认**，设计文档里也还没改。

| 项目 | 设计文档 | 现在的游戏 | 为什么 |
| --- | --- | --- | --- |
| 砸毁时间 | 1、2、4 秒 | 2.5、7、16 秒 | 按文档的数值，机器人反方太强 |
| 半场提前结束 | 没提 | 货全部救完或砸完就结束，直升机提前赶来 | 没货可抢时干等没有意义 |
| 救货方式 | 搬回车上的货箱 | 搬进车旁的黄色区域就自动飞进货箱 | 货箱在高处，这样操作简单 |
| 货车 | 翻车 | 歪着，没翻过来 | 这样从上方能看到货箱里的货 |
| 捏脸 | 第一版要做 | 没做 | 时间紧，分工 v2 里提议先砍，未确认 |
| 开场翻车动画 | 第一版本来就不做 | 没做，货物落点提前摆好 | 同左 |
| 界面语言 | 没写 | 英文 | 分工 v2 里的提议，未确认 |
| 大锤 | 没写 | 单手抡 | 角色手短头大，双手够不到同一根锤柄 |
| 大件颜色 | 没写 | 紫色金边 | 原来的橙色和橙队撞色 |
| 地图边界 | 没写 | 白色围栏和路障 | 让人看得出边界在哪里 |
| 新的小障碍 | 没写 | 被撞弯的护栏（公路右侧 z=-14 到 -22）和两块路牌 | 讲清楚货车是怎么冲出去的 |
| 关卡数量 | 4 关，打完一轮 | 选关页有 6 个位置，第 1 个是教学关（设计文档的第 1 关），5 个占位。玩家自己选一关打，打完不进下一关 | 用户要求。设计文档还没改。怎样对应 4 关、第 5、6 关做什么、还要不要 4 关连打和总结算，都要用户决定 |
| 镜头 | 斜俯视，类似《荒野乱斗》 | 第一人称，V 切肩后第三人称 | 用户在第 8 步提议。**用户还没玩过，等他玩完再决定是否写进设计文档** |
| 操作 | 键盘优先，4 个动作 | 键盘加鼠标，方向键也能转视角 | 第一人称离不开转视角 |
| 搬货姿势 | 没写明，第一版顶在头上 | 抱在身前 | 第一人称才看得到手里的货 |
| 冲撞判定 | 撞到周围的人 | 只撞面前的人 | 第一人称下撞到身后的人说不通 |
| 小地图、方向标记 | 没写 | 有 | 补上第一人称看不到全场的问题 |
| 关卡名 | 林间小路、山间弯道、雨后河滩 | FOREST ROAD、MOUNTAIN PASS、RIVER FLATS | 界面是英文，英文名是我起的，未确认 |

**谁说了算：**

| 内容 | 由谁控制 |
| --- | --- |
| 角色移动 | 角色的拥有者（NetworkTransform 设为 Owner） |
| 冲撞判定、倒地、掉货、搬货归属、砸货耐久、计时、比分、称号 | 主机 |
| 地上货物的物理 | 主机（NetworkRigidbody） |
| 一人搬的货 | 主机定谁在搬。各电脑在本地摆放：自己搬的在手里，别人搬的在胸前 |
| 瞄准 | 拥有者决定对着哪件货，主机只查距离和状态 |
| 两人合搬 | 主机取两人输入的平均方向移动大件 |
| 动画、表情、音效、特效、直升机、第一人称的手、货物裂开和碎块 | 各电脑自己播放，不影响规则 |

**主要数值：** 跑速 6.5；冲撞冷却 3 秒（人少一方 2 秒），冲刺 0.28 秒；倒地 1.5 秒，起身后免疫 2 秒；小件 12 件，搬运速度 ×0.9；中件 6 件，×0.7；大件 2 件，×0.5，要两人搬。人少时货物按比例减少。

**第 1 关布局：** 道路沿 Z 轴，可走范围约 X ±23、Z ±50。货车在 (11, 0, -33)，抢救区域半宽 5、半长 7。正方在货车旁出生，反方在 Z=45 出生。两个大件在 (-15, 12) 和 (16, 16)。

**Animator 参数：** Speed、Rate、Carry（0 无、1 单人、2 合搬）、Dash、Knocked、KnockedRate、Mood（1 欢呼、2 生气）、UpperPose（1 搬小件、2 砸、3 甩手、4 搬中件）。

| 27 | 客户端拿起货后马上又松手 | 按 E 只发“交互”，主机按当前状态切换，有延迟时连按会抵消。改成明确发“要拿这件”或“要松手” |

## 10. 接手时要遵守的

工程规则在仓库的 `AGENTS.md`，下面是最容易出事的几条：

- Unity 用 6000.6.1f1，NGO 用 2.13.x，不升级，不随便加包。
- 角色不直接读键盘，统一走 `ICharacterInput`，这样机器人和自动测试才能用。
- 数值放 `GameConfig` 和 `CargoDefinition`，玩家看到的文字放 `GameText`。
- 写 `NetworkVariable` 和判定规则都只在主机上做。特效和动画不能影响规则。
- 联网物体都从预制体动态生成，新增的要在 `RoomService.Awake` 注册。
- `BuildAll` 会覆盖手工改过的资源。
- 放进可玩区域的东西要有 `Blocker` 碰撞，或者矮到走过去也不奇怪。高的东西不要放进 `OutskirtsIsFree` 排除的区域，会挡住直升机镜头和地图南端。
- 改完至少跑一局机器人对局，确认 `errors=0`。
- 模型、贴图、音频走 Git LFS，`.gitattributes` 已配好。
- 同一时间只能有一个 Unity 打开这个工程。

**用户的习惯：**

- 用简体中文回复。
- 文档类成果存成 PDF 放进 game design 的 `文档/` 文件夹，不要新建线上文档。这个文件夹只放和游戏有关的东西。
- 改游戏时一步一步来，每步都能玩，做完再问下一步。写文档时喜欢直接看完整初稿。
- 提交和推送前要先问。不要动队友的分支（Dino、Gattuso、milkdragon），不要改 `main` 的保护设置。
- 下载文件前要说明文件名、来源和大小。
