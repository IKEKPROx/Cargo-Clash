### 2026-11-17 第 21 步：主菜单和开场动画返工（Claude Code）

用户看了第 20 步，说“太丑了”“手都扭曲了”“页面太 ai 味了”。只重做主菜单和它后面的循环，别的不动。

- **开场循环（20 秒，可以无缝重播）。** 分镜是用户和 GPT 定的：车在路上开 → 车斗里高个子靠着鹅箱、抱着手臂睡觉，车压过一个坑，他被颠起来又落回去 → 镜头绕到车头 → 司机打瞌睡，头垂下去，右手滑到腿上，车慢慢往右偏 → 副驾发现了，扑过去从侧面抓住方向盘，司机惊醒，两人拉扯，方向盘左右打，车跟着左右摆 → 司机抢回来瞪他，副驾手一滑缩回座位，扭头赌气 → 拉回远景，接回开头。镜头一直在动，不切进驾驶室：车内那段从车头前方、司机这一侧透过前窗拍，副驾扑过来时脸正好挤进司机这边的窗。
- **手。** 握方向盘的手是拳头绕着轮圈，和握锤柄同一套算法（`rim_hand`，轮圈穿过拳心 `GRIP_CENTER`，手绕轮圈转到顺着前臂）。用户看了第一版还说“手拐了”：副驾抓方向盘时手腕弯到 70° 左右，司机一直 48° 左右，因为只绕轮圈转不够，前臂和轮圈的角度不对时手腕还是要折。现在每一帧还要找两样：手肘绕“肩—手”连线转到哪里，轮圈斜着穿过手掌多少度（握拳本来就允许 25° 左右的斜），选手腕最直的组合，同时手肘不进身体（每个候选都按 `CrewRig.apply` 的步骤算，所以烘焙出来的就是选中的那条手臂），并且和上一帧接近，免得手臂抖。放在腿上的手也部分顺着前臂（`free_hand` 的 `follow`）。结果（相对站立时的手腕）：司机最多 17°，副驾抓方向盘时大多在 30° 以内，最急的几帧 38°，高个子不超过 30°。`-- --report` 会打印每半秒里超过 35° 的地方。伸手途中手指张开、手指在前，松手时先张开再收回。检查用的是 Unity 里逐帧渲染的近景（下面的预览工具）。
- **修了第 20 步驾驶室的错位。** 座椅、转向柱、踏板在 Unity 里左右是反的（她的 FBX 导入时 X 轴反了，GPT 按 Blender 坐标摆的），司机其实坐在两个座位中间，转向柱接到了副驾那边。现在 `make_menu_truck.py` 里一侧的东西都按 Unity 坐标写，再用 `T()` 换成 Blender 的。副驾的座位往中间挪了一点（x = -0.40），他够得着方向盘。驾驶室后墙改成深蓝，脸和黄帽子更显眼。
- **表情。** 用她的捏脸形状键：EyeSquint 闭眼（打瞌睡、睡觉）、EyeSize 和 BrowHeight 睁大眼（惊醒、发现）、Smile 负值咬牙和赌气。时间轴逐帧给权重。
- **车。** 方向盘转角、车跟着方向的偏航和横移、车身侧倾、压坑的颠簸，全部写在 `Assets/Game/Models/MenuLoop.json`，和人物动作用同一个时钟。车身的颠和侧倾加在新加的 `BodyVisual/Menu_Sway` 上，车斗、货、人物都在它下面（`BodyVisual` 每帧被 `RoverTerrainAnimator` 重写，直接加会被盖掉）。远景跟着车的行驶，不跟着摆，所以能看出车在晃；车内那段跟着车身，所以窗外在晃。
- **菜单。** 去掉调度夹板、螺丝、“CARGO CO. / 准备发车”这些小字和右上角的员工档案卡，回到游戏风格：左边一列，Logo 下面是橙色大按钮“和机器人练习”（Astra 的金条箱贴在左端，探出按钮外），蓝色“创建房间”（卡车），房间码加绿色“加入”，最下面三个带图的小按钮：角色（Astra 的安全帽）、设置（齿轮）、退出（电源）。按钮面是新画的 `UI_ButtonGloss.png`（上亮下暗、顶部一道柔光），字是 Lilita One 加深蓝描边和硬投影。文字都用原来的 `GameText`，中英文都有，GPT 加的那几句已删。底部的按键提示条不放了，开局卡片上有（`BuildIntroCard`）。菜单在 `CargoClashBuilder.Title.cs` 的 `BuildMenuPanel`，所以以后运行生成脚本也是这一版。画面用相机的 lens shift 往右挪出左边这一列的宽度（`MenuDeliveryLoop.menuShare`），透视不变；切到选关、设置、角色页时慢慢移回中间。
- **验证。** Mac 包 0 错误；菜单点击测试 45 项全过（`DONE errors=0 timedOut=False`，含中英文切换、设置页、选关、角色页、开房，改手之后又跑了一遍）；无窗口机器人整局 `RESULT orange=470 blue=530`、`DONE errors=0 timedOut=False`；20 秒循环在实机里录了 121 张看过，拉扯那段逐帧看了手。偏好设置测试前导出、测试后导回。Windows 包没有重打。

怎么改这一段：

1. 动作、镜头、表情、车的晃动都在 `Tools/blender/make_menu_animation.py`。在仓库根目录用 Blender 运行（加 `--factory-startup`）。`-- --timeline` 只重写 `MenuLoop.json`（镜头、方向盘、表情，几秒钟），`-- --only Short` 只烘焙一个人，`-- --report` 打印每人手腕最大弯曲。它从仓库外的 `独立建模/` 读 Astra 的人物原件。
2. 驾驶室和方向盘在 `Tools/blender/make_menu_truck.py`，从 `独立建模/运输载具_v07` 读她的车。座位、方向盘的位置和 `make_menu_animation.py`、`CargoClashMenuPresentation` 里的数要一致。
3. 菜单的图：`make_ui.py -- --only menu`（按钮面和三个小图）。
4. Unity 里运行 `Tools > Cargo Clash > Apply Menu Presentation`（命令行 `-executeMethod CargoClashMenuPresentation.Apply`）。它把车内、人物、车斗里的货、车内灯和菜单重新放一遍，可以重复运行。
5. 不打包就能看：`-executeMethod MenuLoopPreview.Render -previewOut 文件夹 -previewTimes "1,5.2,11.3" -previewUi`，十几秒出图；`-previewShots "名字:秒:x,y,z:x,y,z:视野"` 放一台车身坐标里的相机拍特写，`-previewBones` 打印骨骼位置。编辑器里没有播放循环，蒙皮网格不会跟着骨骼更新，工具已经强制每次渲染重算；不这样的话画出来的是旧姿势，会误以为动作没生效。

没做的：每关自己的开场动画（用户说以后再针对每关做）；Windows 包。车内机位、车斗镜头、表情强弱是我选的，用户还没看过。

### 2026-11-12 第 14 步：重做两种工具的检视动画（提交 `9af16c1`）

用户玩了一遍，说检视动画会穿模、没跟手配合好，两边都要重做，尤其是破坏者（锤子）检视的过程中手腕都歪了。

- **原因：** 旧的检视是先摆工具，再把手贴到把手上，手只能绕把手转。量出来锤子举起来看时，锤柄和前臂只差 20° 左右，手要往旁边弯 60–70° 才握得住，这就是“手腕歪了”（人的手腕往小指那边最多弯 30° 左右）。平时拿锤子的姿势也是这样（前臂转了 129°，手腕弯 48°），但手大多在画面下边缘外面，看不出来；一检视手进了画面就露出来了。穿模有三处：锤子在手上转圈时右手张开，锤柄从手掌里扫过；“在左手掌上掂两下”时左手竖着，锤头没落在手掌上，还穿过手指；收集器像手枪那样翻跟头时吸口转到镜头前，手也张着在下面。
- **做法：** 关键帧改成写右臂的关节：手腕在哪里、前臂转了多少、手腕往小指那边和往手心那边各弯多少（`Joints`），工具挂在手上，跟着手走。这样手腕只会弯到人能弯的角度。开头和结尾的键是从平时的拿法反算出来的关节（`ReadyJoints`），所以接得上。手只在关键帧里写的地方，没有弹簧，不会落在工具后面。代码在 `FirstPersonRig`，规则写进了 `AGENTS.md` 第一人称一节。
- **先在 Blender 里做：** 写了一套和 `FirstPersonRig` 同样算法的预览（`过程文件/工具/检视预览/`），先确认和游戏截图对得上（锤子的位置和大小一样），再按游戏的镜头渲染，逐帧检查手腕角度、前臂转了多少、工具有没有插进手或手臂、两手有没有碰到、离眼睛多近。试过几种想法，下面几种不行：
  - 手肘抬起来让前臂横着：手腕是直了，但手肘一抬，拇指自然朝下，要把锤子立起来，前臂得转 100° 以上。所以举着锤子看要手肘朝下、手放低在胸前。
  - 左手掌拍锤头让它转起来、锤头敲左手掌：手掌平贴锤面时，粗袖口会插进锤头 3–8 厘米，除非手腕往后弯 60° 左右；左手掌朝上接锤头要前臂转 110°，接的位置还在画面底边外面。
  - 两手横握锤子：锤头跑到左下角，一半在画面外。
- **锤子（3.4 秒）：** 左手顺着锤柄滑下去离开，右手把锤子举到面前，侧面对着你，拳头在画面底下；手指捻着锤柄转，先看一个锤面，再转过去看另一个，前臂跟着微微倾斜；手腕一抖，锤子在松开的拳头里转一圈半，往上滑一点再落回拳头里（咔一声）；掂一下，锤头的重量把手往下带；放回平时的样子，左手从下面顺着锤柄握回去。
- **收集器（3.3 秒）：** 左手顺着前握把滑下去离开，右手把收集器竖着举起来，先给你看左侧，再翻过去看顶上；往下一沉再往上一抛：握把顺着自己的方向从拳头里滑出去，出来后手才张开，收集器在手掌上方绕自己的长轴转一圈，再顺着原路落回拳头里；然后平端着朝前方的天空试喷一下（有气团和后坐），收回。原来那个“对着自己的脸喷一口”去掉了，因为要把吸口放到镜头跟前。

## 10. 接手时要遵守的

工程规则在仓库的 `AGENTS.md`，下面是最容易出事的几条：

- Unity 用 6000.6.1f1，NGO 用 2.13.x，不升级，不随便加包。
- 角色不直接读键盘，统一走 `ICharacterInput`，这样机器人和自动测试才能用。
- 数值放 `GameConfig` 和 `CargoDefinition`，玩家看到的文字放 `GameText`。
- 写 `NetworkVariable` 和判定规则都只在主机上做。特效和动画不能影响规则。
- 联网物体都从预制体动态生成，新增的要在 `RoomService.Awake` 注册。
- `BuildAll` 会覆盖手工改过的资源。
- 放进可玩区域的东西要有 `Blocker` 碰撞，或者矮到走过去也不奇怪。高的东西不要放进 `OutskirtsIsFree` 排除的区域，会挡住直升机镜头和地图南端。
- 改完至少跑一局机器人对局，确认 `errors=0`。
- 模型、贴图、音频走 Git LFS，`.gitattributes` 已配好。
- 同一时间只能有一个 Unity 打开这个工程。

**用户的习惯：**

- 用简体中文回复。
- 文档类成果存成 PDF 放进 game design 的 `文档/` 文件夹，不要新建线上文档。这个文件夹只放和游戏有关的东西。
- 改游戏时一步一步来，每步都能玩，做完再问下一步。写文档时喜欢直接看完整初稿。
- 提交和推送前要先问。不要动队友的分支（Dino、Gattuso、milkdragon），不要改 `main` 的保护设置。
- 下载文件前要说明文件名、来源和大小。
