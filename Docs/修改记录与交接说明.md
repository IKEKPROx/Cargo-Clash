- **抡锤的手腕：** 量出来原来挥锤时手骨和前臂的夹角最大到 140–150°（人的手腕大概 40° 就到头了），重锤和蓄力也是。一是手握锤柄的方向写死了，不管前臂从哪边来；二是砸下那一刻前臂几乎和锤柄在一条线上。现在手会绕锤柄转到顺着前臂的方向（锤子跟着右手转，锤面一直在挥动的平面里），手肘也转到让手腕弯得最少的位置；砸下那一帧的手的位置是给每种体型试了几百种摆法挑出来的（`STRIKE`：手在肚子前，离身体近一点，锤柄朝下 50°，左手往右手滑近）；下砸和收锤各加了一个过渡帧，锤子和左手不再扫过胸口；身体后仰蓄力、前倾砸下时头会往回收，眼睛一直看着要砸的地方，以前是仰头看天。第一人称的手本来就会顺着前臂转，连拍看过没问题，没有改。

- **测试中发现的：** 开始页面的自动点击测试有一项（体型、帽子、眼镜按钮）在这台电脑上失败，原因不是这次的改动：测试假设帽子从默认值开始，而用户自己选过的造型存在本机（帽子是 Beacon），按“下一顶”就对不上。改成按开始时的值算。顺带发现游戏的本机设置存在 `~/Library/Preferences/com.Unity-Technologies.com.unity.template.urp-blank.plist`（工程的包名还是 URP 模板的），不在 `unity.COMP4122 Cargo Clash Team.Cargo Clash.plist` 里；改包名会让大家已经存的造型和设置丢掉，先没改。另外，用户存的设置里视角是肩后第三人称，所以平时看到的就是第三人称的抡锤动作。
- **测试：** 见第 7 节“第 13 步之后”。

## 6. 怎么生成、构建、测试

先退出打开这个工程的 Unity。`R` 是工程路径。

内容分三层，改上游要往下重跑：

1. `Tools/blender/*.py` 写出 `Assets/Game/Models/*.fbx` 和 `Assets/Game/Textures/*.png`，需要 Blender 5.2。这些文件已经在工程里，不改模型就不用跑。
2. `CargoClashBuilder.BuildAll` 从 FBX 生成预制体、材质、Animator、教学关场景、开始场景、界面。**它会覆盖手工改动**，手工改过这些资源后就不要再运行它。

## 10. 接手时要遵守的

工程规则在仓库的 `AGENTS.md`，下面是最容易出事的几条：

- Unity 用 6000.6.1f1，NGO 用 2.13.x，不升级，不随便加包。
- 角色不直接读键盘，统一走 `ICharacterInput`，这样机器人和自动测试才能用。
- 数值放 `GameConfig` 和 `CargoDefinition`，玩家看到的文字放 `GameText`。
- 写 `NetworkVariable` 和判定规则都只在主机上做。特效和动画不能影响规则。
- 联网物体都从预制体动态生成，新增的要在 `RoomService.Awake` 注册。
- `BuildAll` 会覆盖手工改过的资源。
- 放进可玩区域的东西要有 `Blocker` 碰撞，或者矮到走过去也不奇怪。高的东西不要放进 `OutskirtsIsFree` 排除的区域，会挡住直升机镜头和地图南端。
- 改完至少跑一局机器人对局，确认 `errors=0`。
- 模型、贴图、音频走 Git LFS，`.gitattributes` 已配好。
- 同一时间只能有一个 Unity 打开这个工程。
